3. カテゴリ別評価

3.1 設定ファイル（CLAUDE.md / GEMINI.md）

✅ 良い点

  • 具体的で検証可能なルール: 「sqlite3.Row → dict(row)を使う」のような即座に適用可能な対処法
  • 「よくある問題と対策」テーブル: 過去の失敗から学んだ知見が体系化されている
  • 双方向同期ルール: CLAUDE.md↔GEMINI.mdの同期指示が設定ファイル自体に書かれている
  • 禁止事項が明確: git push禁止、secrets表示禁止、.bak作成禁止など

⚠️ 改善の余地

  • 行数超過: CLAUDE.mdは約500行。Anthropic公式推奨は200行以下。長すぎるとドメイン固有のルールが無視される可能性あり（@pro-tein氏調査: Claudeの内部プロンプトに「重要でない内容は無視する」指示が含まれている）
  • モノリシック構造: 全情報が1ファイル。公式は.claude/rules/ディレクトリでのパス別モジュール化を推奨
  • 静的/動的情報の混在: ポート番号やサービスURLと、コーディングルールが同じファイルに共存

3.2 メモリ管理 ★★★★★

✅ 理想的な実装

コミュニティで「Living Document」パターンと呼ばれる先進的な手法を完全に実装:

  • MEMORY.md = キュレーションされた長期記憶（人間の長期記憶に相当）
  • memory/YYYY-MM-DD.md = 生の作業ログ（エピソード記憶に相当）
  • git push/pull = AI間の記憶同期メカニズム
  • AGENTS.mdの象徴的な記述: "You wake up fresh each session. These files are your continuity."

3.3 マルチAI協調 ★★★★★

✅ コミュニティ最先端

大半のユーザーは1-2ツールの使用に留まる中、4ツールの体系的な協調運用を実現。特に以下は独自性が高い:

  • 共有ミステイクログ: AI横断的な失敗データベース。クリティカル度ランク付き。コミュニティに類似事例はほぼ存在しない
  • SOUL.md（行動契約）: 「実行してから報告」「証拠のない完了報告は虚偽報告」 — AIの典型的問題行動への体系的対策
  • 完了条件の厳密な4要件: コード変更→テスト通過、ファイル変更→diff確認、memory記録、設定変更→前後値報告

3.4 自律運転（Heartbeat） ★★★★★

📋 構成

  • 間隔: 5時間ごと / 稼働時間: 07:00–24:00 JST
  • 処理: メモリ読込 → Discord確認 → 状態更新 → Deep Work（任意）
  • 最重要ルール: 「実行してから報告。「やります」「確認します」は禁止。やってから結果を書け。」
  • Deep Work時間制限: 15-20分以内に区切り、次回に引き継ぐ
自律運転方式採用例評価
PM2オーケストレーションeverything-claude-code複雑、Node.js依存
Scheduled Cloud TasksClaude Code公式（新機能）クラウド依存
systemd + cron + heartbeat本環境シンプル、堅牢、自己完結

3.5 セキュリティ ★★★★☆

✅ 良い点

  • 階層化権限モデル（Copilotはcommitのみ、systemd/Caddy変更禁止）
  • secrets管理ルールの明文化
  • Gatewayのloopback制限（port 18789）

⚠️ 注意点

  • danger mode / YOLO mode: Claude/Geminiがフルアクセス権限。エフェメラルVPS（2日で消える）前提では合理的だが、認識して運用する必要あり
  • MEMORY.md経由のプロンプトインジェクション: 理論上のリスク。自動実行禁止ルール追加で防御強化可能
